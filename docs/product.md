# Product and UX

## Product sentence

Build, edit, translate, extend, preview, and publish a beautiful website from tend.host while keeping the result as ordinary source code and content.

## Primary audience

The primary user has a goal—“make a portfolio,” “publish my writing,” or “launch my business”—but does not necessarily know what a repository, route, build process, or DNS record is. Expert users receive deeper evidence and controls without burdening the default path.

## Default workflow

1. Choose the kind of site.
2. Choose a reviewed visual direction.
3. Confirm the suggested pages and features.
4. Add a name and identity.
5. Review the plan, then explicitly create it.

Editing happens in a modular Studio:

- **Structure** — pages and collections;
- **Canvas** — responsive block composition and content;
- **Inspector** — only the selected block's meaningful options;
- **Library** — themes, components, media, and translations;
- **Publish** — change summary, checks, deployment evidence, and rollback truth.

Each responsibility gets a distinct workspace or URL-addressable state. Mobile uses purpose-built navigation and sheets rather than a compressed desktop canvas.

## First release scope

- Create reviewed SvelteKit sites.
- Adopt compatible existing repositories safely.
- Manage pages, posts, docs, media, and localization.
- Compose responsive blocks.
- Produce isolated previews.
- Publish through durable tend.host operations.
- Assign domains through tend.host.
- Offer optional user-configured AI assistance with preview-before-commit.

WordPress parity, arbitrary pixel dragging, hidden databases, and unreviewed runtime plugins are not v1 goals.
